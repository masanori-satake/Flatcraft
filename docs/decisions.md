# 決定事項

## 2026-11-20

- **start.bat 実機テスト合格**（本人の Windows PC で画面表示を確認）。サーバーの後片付けは、最小化されている小さなサーバーウィンドウを閉じるだけ。インストールも外部への書き込みもなし
- **デモは自動ループにする**：話しながら手動操作するのは大変なので、キャラクターが歩く・ジャンプを繰り返す自動デモモードを用意し、話者は喋りに集中する。パネルの値変更による動きの変化は従来どおり見せる
- **ゲーム感を足す**：障害物と、流れていく背景（横スクロール）を入れる。今の静止した画面ではゲームらしく見えないため
- **コード表示を再設計する**：「なかみを みる（コード）」の端に寄った狭い表示はやめる。日本語で書いた擬似コードではなく、よりリアルなコードと、その解説を左右に並べる構成にする。子供だましっぽく見えるのは印象が悪い。コード自体は読み取り専用・パネルと数字連動、という従来の原則は維持する

## 2026-11-10

- リポジトリ名は **Flatcraft**（Minecraft方式の先頭だけ大文字。CamelCaseの FlatCraft ではない）。黒板に限らず「3次元ではない2次元のMinecraftみたいな感じ」を表す
- **Private** リポジトリとする（学校名を含む資料のため）。GitHub Actions は使わない（静的・ビルド不要のため不要。Privateでも枠内では実行可能）
- **CodeRabbit は Off**：`.coderabbit.yaml` で自動レビューを無効化し、サクサク作る
- アプリの役割は2つに絞る：①オープニングの動く黒板（つかみ＋自己紹介）②中盤の山場での小さな実演（パネル書き換え＋コードを見せる）。残りの講話は PowerPoint 等のスライドが運ぶ
- 3次元の再現はしない。Minecraft風の黒板、学校名の看板、話者のMiiのドット絵で雰囲気を寄せる
- ライブで書き換えるのは右側常設パネル（ドット書体）の値だけ。コードは書き換えず「中ではこう書いてある」を見せるだけ。パネルの値と対応するコードの数字は連動させる
- 学校にちなんだ要素を入れる（学校名の看板、校舎等のモチーフ）。学校名は `CONFIG` の1行に切り出し、正式名称が分かり次第差し替える
- デプロイ先に GitHub Pages は使わない：GitHubアカウントが Free プランのため Private リポジトリでは Pages が使えない（Pro以上が必要）。また Pro で Private から発行してもサイト自体は一般公開される。当日はリポジトリをチェックアウトするか zip でローカルに持ってきて、ローカルサーバー（localhost）で動かす。PWAの Service Worker は file:// では動かないため、localhost 配信を正とする
- 当日の起動はワンクリックにする：Windows は `start.bat` のダブルクリックで、PowerShell標準の HttpListener サーバー（`server.ps1`、追加インストール不要）が起動してブラウザが開く。コマンドを打つ手順は当日の導線に入れない（あたふた防止）。`server.ps1` は PowerShell 5.1 の文字コード事故を避けるため ASCII のみで書く
- デモの題材は Minecraft のような身近なソフトのミニ版。Soloシリーズのカタログ紹介はしない（中学生には地味なため）

## 2026-11-09

- 講話は30分×2セット形式と判明。有休は十分にあり、平日開催は障壁にならない
- 社名・会社の製品写真は使わない前提で話を設計する（必要になった場合のみ確認する）
- 貫く一文：「ソフトは魔法じゃなくて、誰かが書いた命令の集まり。その命令を考えるのがエンジニアの仕事」

## 2026-11-26 看板から学校名を無くす（0.5.0）

- 当初は「学校名の看板」で学校にちなんだ要素を入れる方針だったが、取りやめる。看板は「職業講話へ ようこそ！」だけにし、学校名は画面のどこにも出さない。
- 理由：生徒が自分のChromebookで GitHub Pages 版を開いて試す形が視野に入り、公開版（仮置き）と当日版（実名）の二重管理そのものが不要になった。どの学校でも最初から通用する形が、道具としての寿命も長い。
- これにより、公開側を仮置きにしてローカルだけ実名に差し替える運用（差し替え→push→復元）も廃止する。
