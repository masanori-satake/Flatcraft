# 職業講話の流れ（構成案 v1）

- 日時：2027-01-20（水）、中学1年生対象
- 形式：30分 × 2セット。生徒は聞きたい職業を2つ選び、前半・後半で教室を移動して聞く（聞き手は自ら選んで来る＝興味がある側）
- 期待されている役割：「ソフトウェアエンジニア」をしている人として、職業について話す
- 貫く一文：**「ソフトは魔法じゃなくて、誰かが書いた命令の集まり。その命令を考えるのがエンジニアの仕事」**

## 配分

| 時間 | 内容 | メモ |
|---|---|---|
| 0〜3分 | つかみ＋自己紹介 | Flatcraftの黒板で。看板、ドット絵キャラの会話窓 |
| 3〜9分 | ミニワールドを見せる | 自動デモでキャラが勝手に歩く・跳ぶ（横スクロール、障害物を自動で跳び越える）。話者は操作せず喋るだけ。仕組みの説明はまだしない |
| 9〜15分 | 中身を覗く（山場） | コード画面を黒板いっぱいに開ける（左に本物風のJavaScript、右に日本語の解説）。パネルで重力／ジャンプを生徒に決めてもらって変えると、コードの数字も連動して光る |
| 15〜21分 | エンジニアの仕事は、この繰り返し | 困りごとを聞く→命令に分ける→作る→試す→バグを直す。UI（ボタンの置き場所を考える）も仕事 |
| 21〜25分 | 普段の仕事とのつながり | 正直な橋渡し：「普段はゲームではなく仕事の画面」。OmniView-SoloのBefore/Afterを1枚だけ。AIが下書きを書く時代でも、決めて確かめるのは人 |
| 25〜28分 | 自分の歩み＋伏線回収 | 下記の実話から3場面だけ使う |
| 28〜30分 | 質問 | 想定質問への答え方を事前に決めておく |

## 実話の素材（25〜28分用、詳細は別途）

使う場面は3つに絞る：

1. 小学6年：両親と泊りがけで秋葉原に行き、NEC PC-6001（パピコン）を89,800円で買った。当時は「パソコン」ではなく「マイコン」、家庭用ゲーム機もない時代
2. 中高：パソコンから離れ、バスケ・駅伝・水泳の掛け持ちとギター。成績は入学時上位→卒業時下位で一浪。それでも「おしゃべりできるロボットを作りたい」で理系へ。暗記科目が苦手で、公式の少ない数学が好きだった
3. 大学院：反動で勉強に熱中。研究はボルツマンマシン（今のAIのご先祖さま世代）。バイト代で30万円以上のパソコンを買い、朝から晩まで自分のプログラムを書いた

締めの回収：おしゃべりロボットの夢とAI研究が一周回って、今のAI駆動開発を制御する仕事につながっている。「今は地味に見える興味でも、捨てずに持っていると何十年か後に真ん中に来ることがある」

※ 学生時代から就職までの話は、別途詳しく聞き取りしてから別ドキュメントにする。

## 生徒の関心（想定）

- どんな人が向いているか：数学の天才でなくてよい／パソコンに張り付く人でなくてよい。「なんで動く・壊れるが気になって試す人」「面倒に気づいて直したくなる人」「人と話して使う側を考える人」
- どんな勉強をするのか：①今の勉強では、数学＝順序立てて考える力、国語＝人やAIに言葉で伝える力、英語＝マニュアルを読む力。プログラミング経験は必須ではない　②なった後も勉強は一生続く仕事

## Soloシリーズの扱い

シリーズを並べて見せるのは中学生には地味（価値の前提がオフィスの面倒さのため）。実例は OmniView-Solo（教室のホワイトボード補正、学校の場面そのもの）のBefore/Afterだけに絞り、他は「自分の道具を公開している」証拠として数と言葉だけで触れる。

## 未確認（主催者・学校へ確認する）

- 質疑応答は30分に含まれるか／移動・着席で実質何分か
- 学校名の正式表記と、学校らしいモチーフ（校舎、近くのランドマーク等）
- プロジェクター・画面の有無と接続方法、ネット環境
- 回答期限、他の講師の業種
- 会社名をプログラム等に載せる必要があるか（載せる場合のみ会社に確認。話自体は社名・製品写真なしで設計済み）
